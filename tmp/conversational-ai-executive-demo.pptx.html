Operating model

AI decides how to help. Code decides how to execute.

LLM responsibilities

Interpret shopper intent.

Choose a permitted tool.

Ask a clarifying question.

Return a concise, conversational response.

Deterministic service responsibilities

Validate inputs and permissions.

Merge filters across turns.

Inject credentials only at the boundary.

Retrieve, map, and render stable structured data.

Why this matters

The model never calls UACAPI directly and never receives shopper credentials. The UI does not rely on model-generated markup. High-stakes ticket submission is handled by a fixed form, not an LLM action.

Security and trust

Controls are built into the architecture

✓ Read-only tools

The model has no direct UACAPI write path. Commerce tools are explicitly read-only.

✓ Credential isolation

Shopper and integration tokens are used only by backend code and never passed to the model.

✓ Injection-resistant calls

Static GraphQL documents and variables prevent string-built query injection.

✓ Deterministic ticket flow

AI may initiate the form, but cannot submit the ticket directly.

✓ Bounded sessions

Conversation memory, model rounds, and tool calls have explicit limits.

✓ Stable UI contracts

The widget receives mapped models, not raw API payloads or generated markup.
